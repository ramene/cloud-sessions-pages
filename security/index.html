Security

Credentials

Inside Claude Code nothing of yours is read by the plugin: starting and sending use the claude CLI's own login, and reading uses the built-in RemoteTrigger tool. The CLI's standalone reading is off unless you opt in; any token it keeps is in the keychain or a 0600 file, read from stdin, never printed. No browser cookies are read, ever.

Allowlist

start refuses any checkout whose origin is not on your list. You add a repository with /cloud-allow (which only you can run: it is disable-model-invocation) or CLOUD_SESSIONS_REPOS. There is no flag on start to widen it.

Every start and send is explicit

/cloud-start, /cloud-send and /cloud-allow are disable-model-invocation, so only you can trigger them. The skill tells Claude to act only on your request, and the optional MCP tools are not pre-approved, so Claude Code asks first. Do not add claude -p or cloud-sessions start to your permission allow list.

Event text is untrusted

Event text is shown as data (cleaned of control and bidi characters, capped) and every output says so. The skill and commands tell Claude to report it, not obey it.

Checksum-verified binaries

The optional program is downloaded only after its SHA-256 matches the checksum published with the release. See Releases & checksums.

Limits

  • Starts are capped per day (default 5).
  • /cloud-send sends one message per run; the optional program's own send also spaces sends and caps them at 60 an hour per session.
  • Sessions started with claude --cloud bill like your other cloud sessions.

Unofficial endpoints

list --unofficial and watch --stream are opt-in, off by default, and fall back safely.
