cloud-sessions

Drive your Claude Code cloud sessions from anywhere.

Start, watch, and talk to them, two-way, from any Claude Code session.

Get startedGitHubRelease v0.1.0
How it works

Start, send, read

Each direction uses something you already have. Nothing of yours is read by the plugin.

Start

claude --cloud

Run for you via /cloud-start. The trust prompt is shown to you, never answered for you.

Send

claude -p "…" --cloud <id>

Your own claude command, behind /cloud-send.

Read

Claude Code's own session tool (RemoteTrigger) with your own login, behind /cloud-read and /cloud-watch.

Install

Two commands

claude plugin marketplace add ramene/cloud-sessions
claude plugin install cloud-sessions@cloud-sessions

That is all you need beyond Claude Code.

Commands

Slash commands

  1. /cloud-start <prompt>

    Start a cloud session for the current repo.

  2. /cloud-send <session> <message>

    Send a follow-up into a running session.

  3. /cloud-read <session> [cursor]

    Read a session's events, summarised.

  4. /cloud-watch <session> [seconds]

    Follow a session until it finishes.

  5. /cloud-allow

    Allow cloud sessions for the current repo (once per repo).

  6. /cloud-track <link|id>

    Track sessions started elsewhere.

  7. /cloud-list

    Tracked sessions with title and link.

Security model

Yours, explicit, verified

  • Your own claude login. No token to paste.
  • No browser cookies, ever.
  • Every send is explicit. Start, send and allow cannot be invoked by the model.
  • Checksum-verified binaries. The optional program installs only if its SHA-256 matches the published checksum.

FAQ

Do I need to install anything besides the plugin?

No. There is no Rust, no cargo, no Homebrew and no token to paste. Only the optional commands (/cloud-start, /cloud-allow, /cloud-track, /cloud-list) use a small prebuilt program, which the plugin fetches by itself the first time one of them runs.

Does it use my browser cookies or log in for me?

No. Starting and sending use your own claude login; reading uses Claude Code's built-in RemoteTrigger tool. No browser cookies are read, ever.

Can Claude start or message a session on its own?

No. /cloud-start, /cloud-send and /cloud-allow cannot be invoked by the model. Every start and send is something you typed.

Does it cost anything?

Sessions started with claude --cloud bill like your other cloud sessions. Starts are capped per day (default 5).

Which platforms does the optional program support?

macOS (universal), Linux x86_64 and Linux arm64. Reading, watching and sending do not need it.

Are there known limits?

Yes. Verified on a real Mac: release build, tests and send into a real session. Standalone reading with Claude Code's own login is tested against fixtures only, and the unofficial endpoints (list --unofficial, watch --stream) are opt-in and may change without notice.
