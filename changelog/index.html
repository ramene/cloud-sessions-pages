Changelog

The Cloud sessions mod (cloud-sessions-core, the cloud-sessions CLI and the Claude Code plugin) is versioned together and released on tags named cloud-sessions-vX.Y.Z.

0.1.0

First release. MIT licensed (LICENSE in the plugin and in each crate). No prerequisites beyond Claude Code: install is claude plugin marketplace add ramene/cloud-sessions then claude plugin install cloud-sessions@cloud-sessions.

  • Core (cloud-sessions-core, no Tauri): start a session with claude --cloud in a pseudo-terminal (the trust prompt is surfaced, never answered); send with claude -p … --cloud <id> --output-format json; read events from GET /v1/code/sessions/<id>/events with a client-side cursor; repository allowlist, session-id validation and a send rate limit. Opt-in, unofficial: list (GET /v1/code/sessions) and the SSE stream (…/events/stream), both falling back to polling or erroring cleanly.
  • CLI (cloud-sessions start|send|events|watch|list|auth|mcp): JSON output, allowlist only from CLOUD_SESSIONS_REPOS or the config file, persisted daily start cap and per-session send limit, MCP server over stdio. Standalone reading uses a token from the keychain (macOS, Windows) or a private 0600 file (auth set [--file]; the file is the only store on Linux, so the Linux binary needs no libdbus, and it works where an ssh login keychain is locked), or, only after a terminal-only opt-in (auth use-claude-login), Claude Code's own login credential (read at use, never printed or stored).
  • Plugin (cloud-sessions): /cloud-start, /cloud-allow, /cloud-track, /cloud-send, /cloud-read, /cloud-watch, /cloud-list, a skill with the rules, and MCP configuration. The plugin's launcher fetches the prebuilt cloud-sessions program on first use (bundled copy, else a download for macOS universal / Linux x86_64 / Linux arm64 whose SHA-256 must match the published checksum; one plain-sentence error otherwise); only the optional commands (/cloud-start, /cloud-allow, /cloud-track, /cloud-list) need it. /cloud-send uses the user's own claude -p … --cloud. Reading (/cloud-read, /cloud-watch) uses Claude Code's built-in RemoteTrigger tool (get_run_log), which works with your own login and needs no token. /cloud-start and /cloud-send cannot be invoked by the model.
  • Track: cloud-sessions track <link|id> [--title t], track --from-file <path> (every https://claude.ai/code/session_… link, deduplicated and validated) and untrack, as CLI commands, MCP tools and /cloud-track; /cloud-list shows titles and links.
  • Release tooling: cloud/release/build-all.sh builds every target the machine can and writes SHA256SUMS; cloud/release/RELEASE.md describes the 0.1.0 tag (not pushed).
  • Known limits: verified on a real Mac: release build, tests and send into a real session. A claude setup-token token is inference-only and is refused by the events endpoint (HTTP 401), so it cannot be used to read; standalone reading with Claude Code's own login is tested against fixtures only and not yet confirmed live; the unofficial endpoints may change without notice.
